# The user guide's site

A Docusaurus site that renders the facade's guide for the three languages it is written in, with
every example tabbed **Rust / Python / TypeScript**.

It exists because the guarantee `xtask/tests/guide_examples.rs` enforces — every code block is a
byte-for-byte copy of a file `cargo`, `pytest` and `node --test` actually execute — currently
reaches nobody outside Rust. The guide renders only in rustdoc, which is the one place a
`pip install` or an `npm install` user never looks.

## Running it

```sh
cd site
npm install
npm run start        # regenerates the content, then serves it at http://localhost:3000
npm run build        # the same, and fails the build on a broken link
```

There is no deployment and no CI job. This is a local site for now.

## Where the content comes from

**Nothing here is written by hand.** The content tree is generated by

```sh
cargo run -p xtask -- docs-site
```

out of the committed guide markdown, and it is **git-ignored** — the same arrangement
`bindings/mjx-wasm/npm/README.md` has, generated and ignored while its `package.json` is committed.
A committed copy of a derived tree would be a second source of truth.

The generator is `xtask/src/docs_site.rs` and the gate over it is `xtask/tests/docs_site.rs`. It
lives in Rust rather than in this project's own JavaScript because two of the things it has to do
need facts that only Rust source states: the page set and its reading order come from the
`include_str!` graph in `crates/mjx-ooxml/src/guide.rs`, and the vocabulary an intra-doc link may
resolve against comes from that file's `guide_vocabulary!` macro. A JavaScript re-implementation of
either would be the second parser this workspace keeps refusing.

| Section | Source |
|---|---|
| The index and the guide | `crates/mjx-ooxml/docs/guide/` |
| Installing | `bindings/mjx-python/docs/guide/installing.md` and `bindings/mjx-wasm/docs/guide/the_typescript_surface.md` |
| Walkthroughs | `crates/mjx-ooxml/examples/`, with each program's Python and TypeScript twin |

## What is deliberately not here

The guide sets **below** the facade — `mjx-opc`, `mjx-dml`, `mjx-sml`, `mjx-chart` and the three
format crates. The bindings depend on `mjx-ooxml` alone, so a page about a crate underneath it
cannot be tri-language by the layering rule, and a user guide whose examples are Rust-only across
most of its pages is a rustdoc mirror rather than a user guide. Those pages stay in rustdoc, for
contributors, and this site links out to them wherever a facade page already pointed a reader there.

The consequence worth naming: **feature-level instructions** — add a chart to a slide, style a
range, build a table — live in those format-crate guides today and are Rust-only. Closing that means
writing new tri-language examples through the facade, not importing Rust-only pages.
