# What is generated

Thirteen committed artefacts, all written by `cargo run -p xtask -- codegen`, all listed by
`cargo run -p xtask -- codegen --check`:

```text
namespaces.rs  shared.rs  drawingml.rs  presentationml.rs  wordprocessingml.rs
spreadsheetml.rs  officemath.rs  diagram.rs  wordprocessingdrawing.rs
spreadsheetdrawing.rs  child_order.rs  mod.rs  COVERAGE.md
```

Twelve of them are `crates/mjx-ooxml-types/src/generated/`; the thirteenth is
`crates/mjx-ooxml-types/COVERAGE.md`, a shipped document. Every one opens with
`// @generated by xtask — do not edit.`, and
`the_committed_generated_directory_holds_exactly_the_generated_files` in
`xtask/tests/codegen_drift.rs` fails if one has lost the banner or if a file is there that the
generator does not write.

## The nine simple-type modules

A schema's `xsd:simpleType` declarations become Rust: an enumeration for a token restriction, a type
alias for a numeric one, a `bool` or `Option<bool>` for the `ST_OnOff` family.

| Module | Schema | Emitted | Visibility |
|---|---|---:|---|
| `shared` | `shared-commonSimpleTypes.xsd` | all 27 | `pub` |
| `wordprocessingml` | `wml.xsd` | all 110 | `pub` |
| `spreadsheetml` | `sml.xsd` | all 96 | `pub` |
| `diagram` | `dml-diagram.xsd` | all 66 | `pub` |
| `officemath` | `shared-math.xsd` | all 14 | `pub` |
| `wordprocessingdrawing` | `dml-wordprocessingDrawing.xsd` | all 7 | `pub` |
| `spreadsheetdrawing` | `dml-spreadsheetDrawing.xsd` | all 3 | `pub` |
| `drawingml` | `dml-main.xsd` | **32 of hundreds** | `pub(crate)`, re-exported by hand |
| `presentationml` | `pml.xsd` | **5 of the schema's** | `pub(crate)`, re-exported by hand |

360 simple types in total. **Do not read that table from here** — read it from
`crates/mjx-ooxml-types/COVERAGE.md`, which the generator writes from its own module table and which
`the_coverage_document_s_counts_match_the_committed_modules` re-derives from the committed module
files on every push. The counts above are that document's, restated for orientation; if the two ever
disagree, `COVERAGE.md` is the one with a test behind it.

**Why two modules are a slice and seven are complete.** `wml.xsd` and `sml.xsd` are emitted whole
because `mjx-docx`, `mjx-sml` and `mjx-xlsx` are modelled *on top of* those vocabularies, so a
missing type would become an enumeration invented somewhere else. `dml-main.xsd` declares hundreds
and only the ones a workstream has ported are named, because the un-curated remainder would be
hundreds of names nobody has read — the naming convention is the whole point of this crate, and a
mechanically-expanded name nobody has checked against the spec is worth less than no name. The
allowlists are `DRAWINGML_TYPES` and `PRESENTATIONML_TYPES` in `xtask/src/codegen/mod.rs`, and
`COVERAGE.md` prints each in full.

## The shape of an emitted item

Every enumeration gets the same five things, and nothing else:

```rust
use mjx_ooxml_types::shared::CalendarType;
use std::str::FromStr;

assert_eq!(CalendarType::from_wire("gregorianUs"), Some(CalendarType::GregorianUnitedStates));
assert_eq!(CalendarType::GregorianUnitedStates.to_wire(), "gregorianUs");
assert_eq!(CalendarType::GregorianUnitedStates.to_string(), "gregorianUs"); // Display
assert_eq!(CalendarType::from_str("gregorianUs"), Ok(CalendarType::GregorianUnitedStates));
assert_eq!(CalendarType::from_wire("nonesuch"), None);                     // never panics
```

`from_wire` returning `Option` rather than a `Result` with a diagnostic is the deliberate shape: an
unknown token is a *future or foreign* value, not an error, and the caller decides whether to
preserve it in the unknown bucket or ignore it. `FromStr` exists for the cases that want an error,
and yields `UnknownWireValue`, which carries the offending text.

An enumeration needs no `AttributeCodec` of its own: every generated one spells itself with `FromStr`
and `Display`, so `mjx_ooxml_core::Enumeration<T>` carries all of them. The four codecs that *are*
hand-written — `OnOff`, `TrueFalse`, `TrueFalseBlank`, `HexColorRgb` — are in
`crates/mjx-ooxml-types/src/support.rs`, and they exist because those four are not enumerations.

**Two-valued types are two-valued.** `ST_OnOff` and `ST_TrueFalse` become `bool`, `ST_TrueFalseBlank`
becomes `Option<bool>`, and the normalizers in `support` accept every wire spelling
(`true`/`false`/`1`/`0`/`on`/`off`) while writing one canonical form. `ST_OnOff1` — the `on`/`off`
half of the `ST_OnOff` union — is in `SKIP_TYPES` and is never emitted, because it is subsumed.

## The namespace table

`namespaces.rs` holds one `SchemaNamespace` per schema — 26 of them, one for every schema file of the
Transitional set — pairing the Strict (ISO-29500) URI with the Transitional one Microsoft Office
actually emits:

```rust
use mjx_ooxml_types::namespaces::DML_MAIN;

assert_eq!(DML_MAIN.for_strict(false), "http://schemas.openxmlformats.org/drawingml/2006/main");
assert_eq!(DML_MAIN.for_strict(true), "http://purl.oclc.org/ooxml/drawingml/main");
```

`strict` is an `Option` because not every schema exists in the Strict set — the five VML schemas are
Transitional-only, and `for_strict` falls back rather than inventing a URI.

## The preset-shape tables

`drawingml` carries three functions that come from neither a schema nor a naming table, but from
ECMA-376 Part 1's `presetShapeDefinitions.xml` electronic addendum:
`adjustments_of`, `adjustable_shapes` and `adjustment_bound_guides_of`
(`xtask/src/codegen/geometry.rs` extracts them). They are the mechanical tier of the preset-shape
model: which handles a shape exposes, on which axis, with what default and what domain.

The counts are worth stating precisely, because three artefacts have disagreed about them before and
`crates/mjx-dml/docs/guide/geometry_and_placement.md` had to settle it:

| | | Where it is asserted |
|---|---:|---|
| `ST_ShapeType` tokens, hence `PresetShapeType` variants | **187** | `crates/mjx-ooxml-types/tests/wire.rs` |
| distinct shapes in `presetShapeDefinitions.xml` | **186** | `crates/mjx-dml/tests/guide_formula.rs` |
| shapes with at least one user-facing adjustment | 119 | `adjustable_shapes` |
| `gdLst` guides in the adjustment-bound closure | **334** of the file's 3,923 | `crates/mjx-dml/tests/guide_formula.rs` |

**187 is not 186 and never was.** `upArrow` is a declared `ST_ShapeType` value with no element in
the geometry file, and `upDownArrow` is defined there twice, byte-identical. `adjustments_of`
answers an empty slice for `upArrow` through its `_ => &[]` arm, which
`crates/mjx-ooxml-types/tests/adjustments.rs` pins by name.

## What the generator refuses to emit

These are hard errors in `xtask/src/codegen/`, not warnings, and each exists because the alternative
is silent data loss:

* **Two emitted types that reach the same Rust name**, or two values of one enumeration that reach
  the same variant (`emit::emit_types`). Collapsing two wire tokens onto one variant would make a
  round trip lossy without anything failing.
* **A naming-override row that matched nothing** — `spec::unused_overrides`, called from
  `check_overrides_are_live`. A row naming a type the schema does not declare, or a wire value it
  does not list, is a typo; this is also what makes *wire tokens preserved exactly, never guessed* a
  checked property rather than a convention.
* **An unresolved `xsd:group ref`**, or a child slot whose element lands in a namespace no parsed
  schema declares (`complex::SchemaSet::group`, `child_order::render_table`).
* **A schema in the Transitional set with no row in `UNCOVERED_SCHEMAS` and no coverage**, so a new
  schema file cannot arrive and be silently absent from the document that reports coverage — and,
  since MJXOFF-224, a row whose claim the tables have made unreachable (see
  [Regenerating](regenerating)).
